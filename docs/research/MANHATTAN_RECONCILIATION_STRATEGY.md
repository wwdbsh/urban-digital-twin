## Contract and reconciliation policy

`SourceObservation` is versioned and retains the complete source reference, provider ID, raw category values, normalized categories, geometry, structured address, contact, brand/operator, cuisine, raw/parsed hours status with timezone, accessibility, price/rating only when supplied, valid/observed/ingested timestamps, confidence and uncertainty. `CanonicalEntity` is a reversible merge group: every selected field has observation/source provenance and every disagreement is a `SourceConflict`; null remains Unknown.

Candidate scoring is explainable and deterministic: exact provider ID (same registry and record ID), linked building/address, normalized name/alias/category, ≤30 m spatial distance, and matching brand/phone/website signals contribute fixed weights. A score of 0.72 merges. High-confidence ID contradiction is quarantined only when both records are in the same comparable identity namespace (`registryEntryId`, or a future explicitly shared authoritative namespace); different providers/registries may use unrelated IDs and can merge when independent evidence reaches the threshold. Ties sort by canonical observation ID. This is an identity hypothesis, not truth: source observations are never deleted and unmerged/quarantined candidates remain reportable.

Search ranks exact source ID, exact canonical name, prefix, then contains across canonical name, aliases, structured address, raw/normalized categories, brand/operator, cuisine and relationship IDs. The index also includes every observation ID, source reference ID, registry entry ID, provider, dataset ID, source record ID and canonical ID; Unicode letters/numbers are retained after accent-mark normalization, so Korean and other scripts remain searchable. Field precedence is confidence, observed time, then stable observation ID; conflicts remain visible. “Open now”, current rating/price, accessibility, or current business existence are never inferred.
