## Recommended default

Use an approved local snapshot pipeline, with Overture Places as the broad baseline only after accepting its per-record multi-license obligations, and NYC civic datasets as authoritative supplements for restaurant inspections, licensed businesses, parks, facilities, and statistical boundaries. Keep OSM as an optional approved extract/enrichment source with ODbL attribution/share-alike review. Use MTA static GTFS for service/stop baseline only after written clarification of the catalog's unspecified license; station entrances require a separately verified source. Do not use Google Places as a bulk or persisted canonical directory: if approved later, use request-time Place Details only, with its Google map/attribution, caching, billing, and Terms/Privacy constraints.

The adapter therefore treats every record's provider, dataset, source ID, terms URL, attribution, license class, freshness, and source reference as required. Missing name details, address, phone, website, cuisine, hours, accessibility, ratings, and photos remain `null`; no source is allowed to manufacture them. A reconciled place keeps all source IDs/licenses and emits field-level conflicts instead of collapsing disagreement into an apparently authoritative value.

### Important gaps and uncertainties

- Public portal visibility does not grant a universal license. The registry now approves only the bounded DOHMH pilot and NYC Building Footprints pilot; Overture, OSM, MTA, and unrelated NYC datasets remain `pending`.
- Overture's source mix means a place can have a different license from another place in the same release. The adapter preserves source-level license and attribution; a production tiling/cache policy must be approved against every source class in the release manifest.
- DOHMH is event/history data, DCWP is legal/status data, Facilities is civic inventory, Parks is managed property, and NTA is statistical geography. None alone supplies a Google-like directory, ratings, reviews, photos, or guaranteed live opening hours.
- MTA's official data catalog identifier is verified, but the catalog result available on the evidence date does not specify a license. Station entrance identifiers and geometry need a separately verified official artifact before implementation.
- Exact file sizes, column null rates, and export limits are properties of the chosen dated snapshot and must be recorded by the first approved ingest; this note intentionally does not download or copy a file to estimate them.

## 2026-08-04 bounded DOHMH pilot evidence

The approved first wave queried the official Socrata endpoint with a server-side Manhattan/Flatiron–NoMad–Union Square envelope (`longitude -74.005..-73.982`, `latitude 40.738..40.752`), `boro='Manhattan'`, deterministic `camis,inspection_date,record_date` ordering, and `$limit=50000`. The exact query is recorded in decision 0012 and the response headers are retained beside the ignored raw snapshot. It returned 13,727 inspection rows (12,553,266 bytes; SHA-256 `6cfbbfaa08c7505ccfecd3fe34742ba31e94c98e4a71d959e9816c0faabb1dea`) representing 1,653 CAMIS groups; normalization and ingestion rejected 0 rows, while retaining each inspection observation separately from place identity.

The normalized records checksum is `cfec0c148d438dd1ecde5e5bb0ed1b1cfc8ff9851b360df63e79745b79ebf011`. DOHMH contributes inspection history, not consumer ratings, reviews, hours, current open/closed status, photos, or completeness; `1900-01-01` source sentinel dates remain source observations and are not presented as current dates. The real pilot is therefore a dated inspection-backed restaurant layer, not a Google-like directory.

## Exact first post-approval implementation task

After one source entry is approved and its dated local snapshot is provided by an authorized operator, run the non-destructive CLI with explicit paths and recorded terms metadata:

```sh
pnpm poi:ingest -- --input /absolute/path/approved/places.snapshot.json --output /absolute/path/approved/poi-artifact-v1 --checksum <64-hex-sha256> --ingested-at 2026-08-03T00:00:00Z
```

The command must refuse pending registry entries, network URLs, missing checksums, mismatched terms, and an existing output directory. The approved pilot wrote only immutable manifest/normalized-feature/layer-manifest files after successful validation and captured its source license, WGS84 coordinates, timestamps, counts, checksums, and rejection list; future sources still require their own review.
